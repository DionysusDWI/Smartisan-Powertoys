# AR13 · G2 取证 —— 闸门「按方向判」的**区分性**

> **版本**:v1.0 ｜ **更新日期**:2026-09-16 ｜ **状态**:✅ **G2 判定完成**（★ 但**原判据被实测推翻并更正**，见 §3）
> **上游**:[AR13 计划书](../.paper/plans/AR13-闸门接线与回归套件.md) §3 A8 ／ §6 G2；
> 　[AR13 真机「拒一次」证据](20260916_AR13_闸门真机拒一次证据.md) §6 G2
> **判据（更正后）**：① 真机台账**每一对**相邻档的违规方向**互斥**；② 两个方向的最大违规来自**不同的档位对**；
> 　③ 把真机的一对档**调换**，违规方向必须**跟着翻**；④ 产物字节码里 `worstViolation` **真的**读 `Trend` 字段。
> **本文件自包含** —— 只读它即可接手。

## 1 · 一句话结论

**闸门确实按方向判，证据是「同一张表在两个方向下的违规来自不同的档位对」。**

```
放电方向：违规 268 mA  ← 来自  178 → 497   （变亮反而更省电）
充电方向：违规 724 mA  ← 来自  497 → 2000  （变亮反而更耗电）
```

★ 两个方向**各自**找到的违规是**两对不同的档**，**交集为空** ⇒
方向参数**真的换得动**，而不是"看见任何非单调就报"。

## 2 · ★★★★★ 先说最重要的一件事：**原 G2 判据是错的**

### 2.1 实测把它推翻了

原判据（写在 AR13 计划书 §3 A8 ／ §6）是：

> **「同一批数据换 `Trend` 必须合法」**

我在**真机归档台账**（`.ref/ar13/20260916_094350_tntgo_battery_prefs.xml`，240 条样本）上跑：

| 表 | 本方向 | 换错方向 |
|---|---|---|
| 放电表（5 档） | **违规 268 mA** | **也违规 724 mA** |
| 充电表（4 档） | **违规 356 mA** | **也违规 648 mA** |

⇒ ★ **「换方向必须合法」在真机数据上根本不成立**（四个格全违规），G2 判据**当场假失败**。

### 2.2 为什么 —— 判据隐含了一个**没写出来的前提**

原判据只在**单调数据**上成立：

| 数据形状 | 本方向 | 换方向 | 判据 |
|---|---|---|---|
| **单调上升** | 违规 | 合法 | ✅ 成立 |
| ★ **真机归档（非单调）** | 违规 | **也违规** | ⛔ **假失败** |

真机那份台账的 `|I|` 是 **先升 → 后降 → 再升**（`44→94→178` 升、`178→497` 降、`497→2000` 升）。
⇒ **两个方向各自都能找到属于自己的那一对**。

### 2.3 ★★★ 这里有一个**必须留下的区分**（否则会得出相反结论）

> **「两条都拒」与「方向无关」是两件不同的事。**
> 原判据把前者读成了后者 —— **判据写错，比判据没有更危险：它会让我宣布一个本来成立的结论不成立。**
> （与纪律 ⑲ 同族：**判据算错会让你主动放弃一个正确的结论**。）

⚠️ 顺带纠正一处**上一份证据文档里的说法**：`docs/20260916_AR13_闸门真机拒一次证据.md` §4 写
「把闸门打响的那一对是 `497 → 2000`」—— 那句**只在充电方向下成立**。
放电方向打响的是 **`178 → 497`**（`1612 → 1344`，反向 268 mA）。
两句话都不算错，但**不说方向就会误导** ⇒ 两份文档都按本节口径读。

## 3 · ✅ 更正后的判据：与数据形状**无关**的性质

### 3.1 逐对方向互斥（数学上是恒等式）

对**任意**一对相邻档，令 `Δ = |I|(亮) − |I|(暗)`：

| Δ | 放电方向 | 充电方向 |
|---|---|---|
| `> 0`（变亮更耗电） | 合法 | ★ 违规 |
| `< 0`（变亮更省电） | ★ 违规 | 合法 |
| `= 0` | 合法 | 合法 |

⇒ ★★ **`min(放电违规, 充电违规) == 0` 必须对【每一对】成立**。
这是**互斥**，**与单调与否无关** ⇒ 对**任意真机台账**都能判它。
★ 而若 `trend` 被忽略（两个分支算出同一个数），这一条**必然失败** ⇒ **判据有牙**。

### 3.2 真机实测（本文件的核心证据）

**放电表**（5 档 ／ 4 对）：

| 相邻对 | Δ (mA) | 放电违规 | 充电违规 | 同时违规 |
|---|---|---|---|---|
| `44 → 94` | +129 | 0 | 129 | **0** |
| `94 → 178` | +503 | 0 | 503 | **0** |
| ★ `178 → 497` | **−268** | **268** | 0 | **0** |
| ★ `497 → 2000` | +724 | 0 | **724** | **0** |

**充电表**（4 档 ／ 3 对）：

| 相邻对 | Δ (mA) | 放电违规 | 充电违规 | 同时违规 |
|---|---|---|---|---|
| `23 → 178` | +356 | 0 | **356** | **0** |
| `178 → 497` | −524 | 524 | 0 | **0** |
| `497 → 2000` | −647.5 | 647.5 | 0 | **0** |

★ **同时违规的对数 = 0**（两张表都是）。
★ 逐对取 max **复现**表级 `worst_violation`（放电 268 ／ 充电 724）⇒ 表级汇总不是"只看第一对"。

### 3.3 换得动（决定性一击）

取**真机测到的**那一对 `178 → 497`（Δ = −268）：

| 摆法 | 放电方向 | 充电方向 |
|---|---|---|
| 按真机原样（升/降） | **违规** | 合法 |
| 把两档**调换** | 合法 | **违规** |

⇒ ★★ 违规方向**跟着数据翻** ⇒ 闸门**真的看 `trend`**，不是"看见下降就报"。

## 4 · 设备侧为什么**做不到**（以及这对结论意味着什么）

G2 原话是「在**真机上**验方向区分性」。**做不到 —— 不是没做，是产品里没有那个开关**：

| 事实 | 位置 | 后果 |
|---|---|---|
| `Trend` 是**编译期常量** | `TntgoBklProfile.kt:209-210`：放电表**写死** `Trend.Discharge`、充电表**写死** `Trend.Charge` | 设备上**无法**让某张表用另一个方向判 |
| 每张表的方向 = 样本自己的 `chg` 位 | `TntgoBklProfile.kt:176-180`（`plateaus` 按 `charging` 过滤） | 就算篡改台账的 `chg` 位，也只是**把样本挪到另一张表**，方向**依旧与表绑定** |
| 所以 | —— | 设备侧要换方向，**只能改产品代码重打包** |

★ 但**必须说清这一条不削弱结论**：

1. 「方向参数**换得动**」是**纯逻辑**性质，**不依赖设备**；它在真机数据上被证了（§3）。
2. 「设备上**这条通路**被执行」由 **A8**（真机日志 `放电档位 5 个 ⇒ 反物理`）与
   **④ 接线点判据**（`refreshCurve()` 里两句 `gate(..., Trend.X)` 逐字匹配）共同保证。
3. 「快照产物里**真的有**方向分支」由 **⑥ 字节码**保证（见 §5）。
4. 「最理想的一步」（设备上让同一张表用两个方向各判一次，读两条日志）**只能靠改产品做到** ⇒
   ★ 已作为**候选**列出，**不擅自做**（会引入一个只为测试存在的分析通道，正是 AR13 §0 的禁止项）。

## 5 · 四层证据（都在回归套件里，每一层都能失败）

| 层 | 判据 | 落点 | 摘掉方向后 |
|---|---|---|---|
| **① 真机数据·互斥** | 每一对相邻档 `min(放电,充电) == 0` | `analyze_bkl_curve.py` ⑮ | ✗ 红 |
| **② 真机数据·换得动** | 调换真机一对档 ⇒ 违规方向跟着翻 | ⑰ | ✗ 红 |
| **③ 表级·方向可分辨** | 同一张表两方向的 `worst_violation` **必须不同** | `run_bkl_tests.py` ⑤-G2 | ✗ 红 |
| **④ 产物·字节码** | `worstViolation` 里**真的**读 `Trend.Discharge` 字段 ＋ `dneg` | `run_bkl_tests.py` ⑤-G2 ＋ ⑥ | ✅ 仍绿（**按设计**） |

★ ④ 在"摘掉方向"时仍绿是**正确的**：它读的是**已编译产物**（class 比源码旧就不放行），
而那一轮我只改了 Python 源码、**没有重新构建** ⇒ 产物里当然还是旧实现。
**弱判据不冒充强判据** —— ④ 只证「结构在产物里」，不证数值行为。

**命令与结果**（2026-09-16）：

```
$ python scripts/analyze_bkl_curve.py --selftest
✓ 自检通过 22/22

$ python scripts/run_bkl_tests.py --no-kotlin
✓ 全部通过 19/19          # ③ Kotlin 真执行仍为显式 SKIP（AR13 §2.2 的老缺口，未变）
```

**有牙验证**（临时把 `worst_violation` 的方向分支摘掉，改成"永远按放电判"）：

```
✗ ⑤-G2 调换真机一对档位 ⇒ 违规方向必须跟着翻        ← 红
✗ ⑤-G2 闸门把每一对都判给【恰好一个】方向            ← 红（交集非空）
✗ ⑤-G2 同一张表在两个方向下的 worst_violation 必须不同 ← 红（相差 0 mA）
✗ ① analyze_bkl_curve --selftest                   ← 红（4/22 失败）
```

⇒ ★ **判据不是"能跑通"，而是"盯着闸门"**。

### 5.1 ⚠️ 写这一组判据时踩到的坑：**假绿**

第一版的"两个方向违规来自不同的对"是用**脚本自己重算的 `Δ`** 判的。
⇒ 把方向分支摘掉之后，**它照样绿**（因为重算那部分根本不经过被测函数）。
★ 修法：**集合一律经闸门自己的判读**（`check_mode(pair, trend)`）算出来。
⇒ 这就是纪律 ②「两边各写一遍」的**镜像版**：**判据若自己实现一遍受测逻辑，它就只能自证。**

## 6 · 现在**可以**说什么 / **不能**说什么

| | 声明 |
|---|---|
| ✅ **可以** | 闸门**按方向判**：同一张表在两个方向下，违规来自**不同的档位对**（真机数据实测） |
| ✅ **可以** | 把真机测到的一对档**调换**，违规方向**跟着翻** ⇒ `trend` 真的在起作用 |
| ✅ **可以** | 编译产物里 `worstViolation` **真的**读 `Trend` 字段（`dneg` 一元取负也在） |
| ✅ **可以** | 原 G2 判据（"换方向必须合法"）**在非单调数据上不成立**，已更正为与数据形状无关的形式 |
| ⛔ **不能** | 不能说「方向参数在**设备上**被区分性验过」—— 产品把它写成编译期常量，**没有外部开关**（§4） |
