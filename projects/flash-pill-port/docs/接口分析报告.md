# 闪念胶囊（IdeaPills）系统接口分析报告

> 用途：为"再造一个兼容小米（Android 16，不 root）的个人版闪念胶囊"提供接口对照蓝本。
> 目标方案：语音转写改用 **硅基流动(SiliconFlow)/DashScope 实时语音转写**；UI 重写代码与元素（但学习原版交互）；数据/云/入口全部重做。
> 源：`com.smartisanos.ideapills` v7.0.0 反编译(d=5821 smali) + 曼fiest + dex 字符串分析。

---

## 一、总览：它"对外打了多少接口"

闪念胶囊本质是一个**被系统/生态唤醒的后台胶囊功能**，对外接口分四类：
1. **ACTION / Intent 动作**（它监听或发送）
2. **外部组件/服务**（它跳转、绑定、注入）
3. **ContentProvider / Authority**（它读写的数据源）
4. **权限 + 框架类**（它需要的系统能力）

## 八、→ 你的方案映射（核心）

| 原功能 | 原实现 | 你的实现（小米16 / 不root / 硅基流动·DashScope） |
| --- | --- | --- |
| 语音录"闪念" | sara 语音气泡 + `VIEW_*_VOICE_INPUT_RECORD` + `content://sara/globleBubble` | 自建录音(MediaRecorder/AudioRecord) → **硅基流动/DashScope 实时音频流转写** → 渲染进自绘气泡 |
| 胶囊入口/触发 | 锤子一键/一步/长按 | **通知快捷 + 悬浮球 + 长按音量键/辅助**，或自建侧边悬浮 |
| 胶囊气泡列表 | `ideapills.view.Bubble*` | 学习其交互，自绘(RecyclerView/Compose) |
| 提醒/日历 | `RemindBubbleShowActivity`+`SmartisanDatePicker`+`ADD_EVENT` | `AlarmManager`+`CalendarContract`+Material 日期选择 |
| 分享/转发 | `SEND`/`SEND_MULTIPLE`+gallery/mms/incall | Android ShareSheet + PhotoPicker |
| 云同步 | 锤子云/账户 | **去掉**（个人本地），或自建简单导出 |
| 悬浮窗气泡 | `SYSTEM_ALERT_WINDOW`+`INTERNAL_SYSTEM_WINDOW` | 仅 `SYSTEM_ALERT_WINDOW`（不 root 可得，需用户授权悬浮窗） |
| 大爆炸/一步 | sidebar+BOOM_* | 舍弃（个人版可做"选取文本→记胶囊"） |

## 九、技术要点 / 风险

1. **语音转写**：硅基流动/DashScope 需 `RECORD_AUDIO` + 网络权限；实时(WebSocket/流式)建议封装成 `AudioRecord→AudioStream→转写`，中途可后台（`FOREGROUND_SERVICE_MICROPHONE`，Android14+ 需声明前台服务类型）。
2. **悬浮窗**：安卓 13+ 需引导用户在设置授予"显示在其他应用上层"，个人版可靠。
3. **后台保活**：小米(MIUI/HyperOS)有严格后台限制，胶囊若需后台常驻，会受限；建议用"**前台服务+通知**"与"**使用中**"策略，或做成**按需唤起**（点悬浮球/通知才启动）。
4. **Android16(API36)**：注意 **16KB page size**（原生库需 64 位 + 16KB 对齐）、预测式返回手势、前台服务类型与权限声明。本项目若不引 32 位原生库，重新编译为 arm64 即可规避原"32 位"问题。
5. **数据规整**：建议从零规划数据模型（胶囊类型：文本/语音/图片；状态；标签；时间），不必沿用其 provider。

## 十、建议的开发步骤
1. 用本报告作为**接口对照**，反编译源码(已含于包)参考 UI 与交互。
2. 立项：数据层(本地 DB) → 语音层(硅基流动/DashScope SDK 封装) → UI(气泡列表/编辑/提醒) → 入口(通知/悬浮球) → 悬浮窗 → 权限/后台。
3. 目标 `minSdk>=29, targetSdk=36`，arm64，个人 keystore 签名。
4. 迭代：先做"文本胶囊"跑通，再加"语音实时转写"，再补"提醒/分享"。
