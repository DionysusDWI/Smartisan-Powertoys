# Smartisan Powertoys

> **给锤子/坚果 Smartisan TNT 桌面模式手机加功能的开源工具箱。**
> 一个 APK，内含可插拔的功能模块（mod），并开放对外 API 供其它工程调用。

⚠️ **这是开发预览版（Developer Preview）** —— 功能可用，但**没有经过广泛设备验证**，
接口与行为**可能随时变动**。详见 [已知限制](#已知限制)。

---

## 这是什么

锤子的 **TNT 桌面模式**（坚果 Pro 3 内部代号 `revone`）是一套把手机变成桌面工作站的方案，
但官方生态早已停止更新。这个项目做的事情是：

* **把 TNT 桌面模式缺的能力补回来** —— 外接屏亮度、外设电量、系统状态、性能调度……
* **一个 APK 装完**，不用为了每个小组件单独装一个应用、单独授一次悬浮窗权限
* **模块化** —— 每个功能是一个独立 `mod`，可以单独启停；外部工程也能写自己的 mod

它**不修改系统、不需要 root**。

---

## 功能一览

| 模块 | 做什么 | 需要额外授权 |
|---|---|---|
| **TNT GO 亮度** | 用 TNT GO 键盘上的**亮度键**直接调外接屏背光；屏幕上有 OSD 提示 | ⚠️ **无障碍**（见下） |
| **TNT GO 电量** | TNT 屏上常驻卡片：手机电量 ＋ TNT GO 电量 / 电压 / 电流 / 温度 / 功耗 / 可用时间 | 悬浮窗 |
| **手机性能** | TNT 运行时在手机屏上显示内存 / CPU / 温度 | 悬浮窗 |
| **性能模式** | 抬起 CPU 频率下限（走 QTI perf HAL，**免 root**），对**软解视频**这类持续重负载有实测收益 | 悬浮窗 |
| **实时字幕** | 抓音源送云端实时识别，在 TNT 屏上滚字幕 | 悬浮窗 ＋ **自备 DashScope API Key** |
| **示例·状态卡片** | 写新 mod 的模板，也是契约的测试夹具 | 悬浮窗 |

另外还有一个**图形化设置界面**（功能卡片列表 ＋ 多层同屏管理），以及一套
**对外 API**（AIDL，JSON 载荷），其它应用可以查询/控制这些功能。

## 环境要求

| | |
|---|---|
| **系统** | Smartisan OS / Android 10（SDK 29）及以上 |
| **已验证机型** | **只适用于 Smartisan Nut Pro 3**（DT1901A）＋ **TNT GO** 便携屏 |
| **架构** | arm64 |
| **root** | ❌ **不需要** |
| **构建** | JDK 17 ＋ Android SDK（`minSdk 29` / `targetSdk 35`） |

> ⚠️ **TNT GO 相关模块只对 TNT GO 有效** —— 它们通过 USB CDC-ACM 串口跟屏幕的
> MCU 讲 AT 命令。别的外接屏没有这条通路。

## 安装

### 方式一：直接装预编译 APK（推荐）

从 [**Releases**](../../releases) 下载 `powertoys-v0.3.0-20260915.apk`
（最新版 ⇒ [v0.3.0 发布说明](docs/20260915_开发预览版发布说明_v0.3.0.md)）：

```bash
adb install -r powertoys-v0.3.0-20260915.apk
```

> ⛔ **只适用于 Smartisan Nut Pro 3（DT1901A）。** 其它机型**明确不适用** ——
> 原因见[发布说明](docs/20260915_开发预览版发布说明_v0.3.0.md)文首。

### ⚠️ 装完还有**一步 adb 干不了**的活

**Smartisan 的悬浮窗有【两道门】**，脚本只能过第一道：

| 门 | 怎么过 |
|---|---|
| ① Android `SYSTEM_ALERT_WINDOW` appop | ✅ adb 可自动授 |
| ② **Smartisan 自己的悬浮窗授权** | ⛔ **只能人点**：`手机管理 → 权限管理 → <应用> → 悬浮窗` |

**只过 ① 不过 ② 的症状极具迷惑性**：窗口加得上、bounds 也对、
**logcat 一个错都没有，但永远不显示**。

**另外**：「TNT GO 亮度」模块需要**无障碍服务**，请在
`设置 → 无障碍 → Smartisan Powertoys` 里手动打开（这是系统硬要求，adb 授不了）。

### 方式二：自己构建

```bash
git clone <this-repo>
cd Smartisan-TNT-Secondary
bash scripts/build.sh --list          # 看有哪些可构建目标
bash scripts/build.sh mode-all        # 构建一体化 APK
bash scripts/deploy.sh mode-all       # 构建 + 侧载 + 授 appop + 打印手动待办
```

> ⚠️ `scripts/env.sh` 会去 `toolchain/` 找便携 JDK/SDK —— **那部分没有入库**
> （3 GB，见 [`.gitignore`](.gitignore)）。请自备 JDK 17 与 Android SDK，
> 或改 `scripts/env.sh` 指向你自己的。

## 「实时字幕」需要你自己的 API Key

这个模块**不含任何 API Key**，也不会向作者回传任何数据。
它需要一个 **阿里云百炼（DashScope）** 的 Key，二选一：

* 在应用设置界面里填（存在本机），**或**
* 构建时注入环境变量 `DASHSCOPE_API_KEY`

> ★ 若不填，该模块**只是不工作**，不影响其它模块。

```
├── mod-tntgo-battery/      电量模块
├── mod-perfmode/           性能模式
├── mod-perfmon/            手机性能
├── mod-livecaption/        实时字幕
├── mod-hello/              模板 / 测试夹具
└── perf-probe/             性能诊断工具（按需部署）

.paper/                   ★ 研究结论（硬件、AT 命令、UI 规格、复刻方案、亮度控制…）
.ref/Search-Results/      调研归档（每条都带 URL 与提取出的事实）
docs/                     报告与规格
scripts/                  构建 / 部署 / 校验（含若干**判据工具**）
```

> ### ★★★ 为什么 `applicationId` 是 `com.shware.mode` 而不是 `com.shware.powertoys`
> 换掉它会**丢掉 Shizuku 授权和 Smartisan 悬浮窗授权** —— 那是**两道只能人点的门**。
> ⇒ **「Smartisan Powertoys」是显示名（label），不是包名** ——
> 和 Windows 的 PowerToys 一样，用户看到的是名字，不是 GUID。

## ★ 这个项目的两条工程习惯

如果你要读这里的代码或文档，有两件事值得先知道 —— 它们解释了很多看起来"啰嗦"的注释。

### ① 每个结论都标注**来源**，`推断` 必须显式写出来

数据来源分五类：**实测 / 反编译 / 交接包 / 网络 / 推断**。
文档里出现数字的地方，基本都能找到它是怎么来的。

### ② **"测不出来"也会被写下来，而且不算失败**

例：性能模式对**视频/Web/多任务**的帮助，实测**测不出来**（瓶颈在专用硬解器与磁盘 IO，
不在 CPU 频率）——这条被明确写进了结论，功能定位据此从"通用加速"改成了"重负载场景"。

同理，有些指标**坚决不显示**而不是显示一个猜的数：

* 亮度未知 ⇒ 显示「亮度未知」并降级，**绝不猜一个亮度**（猜错的亮度会把曲线学歪，用户看不出来）
* TNT GO 功耗**扣不掉对外供电**那部分（端口功率实测读不到）⇒ 界面上**必须**标注「含对外供电」
* 亮度-功耗曲线**只在实际测过的亮度区间内插值**，超出实测范围**不外推**

## 已知限制

* **没有广泛机型验证** —— 只在坚果 Pro 3 ＋ TNT GO 上实测过
* **TNT GO 模块依赖具体硬件** —— 换屏即失效（AT 命令是屏幕 MCU 的私有协议）
* **性能模式的收益场景很窄** —— 只对**持续 CPU 重负载**（如 AV1 软解）有效，见上
* **`perf-probe` 是诊断工具**，不是产品的一部分
* 部分文档与注释是**中文**（这个项目的开发过程如此）
