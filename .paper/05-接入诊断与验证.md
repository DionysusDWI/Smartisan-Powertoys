## 1. ★ 三层依赖诊断模型

TNT GO 与手机之间是**三条相互独立的链路**,任一缺失对应一种**特征鲜明的症状组合**:

| 链路 | 承载 | 缺失后果 | 依赖 |
|---|---|---|---|
| **VBUS 供电** | 电力 | 全黑、无背光 | 任意 C 口 |
| **USB 2.0 数据**(D+/D−) | HID 键鼠、音频、摄像头、CDC 串口 | **外设全部失灵** | 需「全功能口」+ 带数据的线 |
| **SuperSpeed + AUX + 完整 CC** | PD 协商 → **DP Alt Mode** | **无画面** | 需「全功能口」+ 全功能线 + 直连(不过 HUB) |

### 症状 → 故障层对照表

| 背光 | 键盘 | 画面 | 判定 |
|---|---|---|---|
| ❌ | ❌ | ❌ | 未连接 / 未供电 |
| ✅ | ❌ | ❌ | **只走了 VBUS** —— 插在「仅供电口」,或用了纯充电线 |
| ✅ | ✅ | ❌ | **USB 2.0 通,DP 缺** —— 线材缺 SuperSpeed 差分对 / DP lane |
| ✅ | ✅ | ✅ | 正常 |

> **这张表是排查的核心工具** —— 看现象就能定位到具体链路,不必逐项试。

### 测试 2 · 全功能 USB + **HDMI 转换插头**

| 项 | 值 |
|---|---|
| 配置 | 全功能 USB-C 线 + **HDMI 转换插头** |
| **结果** | ✅ **成功输出画面** |
| **画面内容** | ⚠️ **手机屏镜像**(不是 TNT 桌面) |
| 问题 | ❌ **USB 信号不稳定** |
| TNT 虚拟屏 | ❌ `state OFF`(未激活) |
| 当前 display 列表 | 仅 `Display 0` + `Display 100000`,**无独立物理屏在线** |
| DP 链路 | 最后为 `dp_display_unprepare: [OK]` + `core:off link:off`(已关闭) |

#### ★ 诊断:USB 不稳定的根因 = 供电崩溃

```
[116561.834622] usbin_collapse_irq_handler: IRQ: usbin-collapse
[116570.774245] usbin_collapse_irq_handler: IRQ: usbin-collapse
[116587.662677] usbin_collapse_irq_handler: IRQ: usbin-collapse
[116588.899898] usbin_collapse_irq_handler: IRQ: usbin-collapse
[116609.485660] usbin_collapse_irq_handler: IRQ: usbin-collapse
```

- **`usbin-collapse` 累计 1476 次**,最近**约每 10–20 秒触发一次** → 输入电压反复跌落
- **输入电流限制持续跳动**:
  ```
  icl_settled = 800000 → 750000 → 800000 → 800000 → 750000
              → 900000 → 850000 → 900000 → 950000 → 900000 → 800000   (μA)
  ```
  在 **0.75–0.95A** 之间来回震荡,说明系统在**反复尝试稳定供电但失败**
- `Max charging current: 900000`(0.9A)—— 仍是 `SOURCE_DEFAULT` 档,非 `SOURCE_HIGH`(3A)

**成因**:HDMI 转换插头**自身要从手机取电**(作为 DP sink + 转换器),而它**不提供 PD 供电** →
手机侧 VBUS 被拉低 → 电源管理反复重试 → 链路(含 USB 数据)被牵连着反复重置。

> 注意这与 TNT GO 直连时**相反**:直连时 TNT GO 是 **Source**(3A)给手机供电;经转换器后供电关系倒转。

#### 为什么是「镜像」而不是 TNT 桌面

| 观察 | 含义 |
|---|---|
| `smt.tnt.virtual.display` `state OFF` | **TNT 桌面根本没被渲染** |
| `global_pc_mode_settings=0` | 未进入 PC 模式 |
| 只有 display 0 与 100000 | 无 TNT 认可的 base display 在线 |

**推断**:TNT 虚拟显示须架在一个通过 `SmtPCUtilsInner.isValidExtDisplayType()` 校验的 base display 之上
(见 `[04](04-小米端复刻方案.md)` §9.1 引 TNT-Anywhere 逆向结论)。
经 HDMI 转换插头后,系统把外接屏当作**普通 HDMI sink** → 走标准镜像路径,**不进 TNT 链路**。
(`mOverrideDisplayInfo` 里那个 "HDMI 屏幕 displayId 15 / state ON" 是**上次连接残留**,不是当前实况。)

#### 处置建议

1. **给 HDMI 转换插头外接供电**(多数 USB-C→HDMI 转换器带 PD 输入口)→ 直接消除 `usbin_collapse`
2. 或改用**带供电的 USB-C 扩展坞**
3. 若目标就是 TNT 桌面(而非镜像),仍需回到 **TNT GO 直连其「全功能口」** 的路径

### 测试 3 · TNT GO 接全功能口后仍无画面

| 项 | 值 |
|---|---|
| 配置 | 用户将 TNT GO 接到手机全功能 USB-C 口 |
| 结果 | ❌ **仍无画面** |
| PD | ❌ `PD=0` |
| Type-C | ❌ `SOURCE_DEFAULT`;`APSD=SDP`(标准端口,500mA) |
| DP ready 计数 | **仍为 14**(无任何新事件) |
| USB 枚举 | ❌ 无新的 `usb 1-1.x: new device` |

#### ★★ 根因:手机 USB 口处于 AOA/Accessory 模式,**不是 USB host**

`dumpsys usb` → `device_manager`:

```
current_functions = [ADB, ACCESSORY]
current_accessory = {
    manufacturer = Smartisan
    model        = HandShaker          ← 配件被识别为 HandShaker
    version      = 1.0
    uri          = http://sf.smartisan.com/sf/release/apk
}
host_connected = false                 ← ★ 手机不是 USB host
source_power   = false
sink_power     = true                  ← 手机是「被供电方」
usb_charging   = true
```

**手机此刻扮演的是「USB 从设备(Accessory)」,被电脑的 HandShaker(AOA 协议)占用。
手机不是 host,自然无法去枚举 TNT GO。**

**这解释了全部症状**:无 USB 枚举、无 DP、`PD=0`、500mA(SDP 标准电流)、`AC powered: false`。

> **重要**:此前的测试 0/1/2 中手机能枚举 TNT GO,说明那时 USB 口确实进了 host 模式;
> 本次是 USB 口被电脑占走所致 —— **与线材、端口位置都无关**。

#### 解法:让 USB 口腾出来

手机已启用 TCP adb(`tcp6 :::5555 LISTEN`),**无线通道可用**:

```bash
adb connect <设备IP>:5555     # ✅ 已验证连接成功(transport_id=2)
```

**操作顺序**:
1. 确认无线 adb 已连上(本工作区已验证)
2. **拔掉手机与电脑的 USB 线** → 退出 Accessory 模式,USB 口转为可作 host
3. **把 TNT GO 插到手机全功能口**
4. 保持 5–10 秒走完协商(真机 4.2 秒)

期间电脑侧通过**无线 adb** 继续监控,不会失联。

## 3. 换线/换口操作要点

1. **必须插 TNT GO 的「全功能」USB-C 口** —— 右侧有两个口,**外侧仅供电,内侧全功能**(视频输入 + 供电 + USB 数据)
   - 识别判据:全功能口通常标有 **USB 三叉戟图标**;仅供电口无标注或标电源符号
2. **线材**:全功能 Full-Featured(USB 3.2 Gen2 / USB4 / 雷电3·4),支持 DP Alt Mode 4 lane,不过 HUB
3. **接上后保持 5–10 秒**,让完整协商跑完(真机 4.2 秒)
4. 信号中断是正常的 —— 换线会触发 Type-C 重协商(先 `dp_display_unprepare`,再重建)

## 5. 关键内核日志速查

```bash
# 供电 / PD
dmesg | grep -E 'smblib_update_usb_type|Type-C (SOURCE|Sink|NONE)'
#   PD=1 → 已协商   SOURCE_HIGH → 3.0A   SOURCE_DEFAULT → 仅默认电流

# USB 枚举
dmesg | grep -E 'usb 1-1.*new|Product: Smartisan|Manufacturer: deltainno'

# DP 链路
dmesg | grep -E 'hpd_high|dp_panel_resolution_info|dp_display_post_enable'
#   dp_display_post_enable 出现 = 显示链路就绪

# 供电功率(手机侧输入 = TNT GO 输出)
dmesg | grep 'healthd: battery' | tail -1
#   iv=输入电压mV  ic=输入电流mA  → 功率 = iv × ic

# 显示面
dumpsys display | grep -oE 'smt.tnt.virtual.display.*state (ON|OFF)'
```
